# Code review summary and enhancements (2026-10-20)

Per-bug detail (what changed, behaviour change, UI test steps, rejected findings) is in [code-review-report.md](code-review-report.md).

## Summary

All 72 verified bugs were fixed. `pnpm typecheck` and `pnpm build` pass. Nothing was run against an Omni instance.

- **Review:** 15 reviewers ran three passes and raised 188 distinct issues. Three more reviewers tried to disprove each one: 159 held up and 29 were rejected. The 159 merged into 72 bugs (1 high, 21 medium, 50 low).
- **Fixes:** a separate reviewer checked each group's fixes and found problems in 8, which were corrected. A final pass fixed 6 conflicts between groups.
- **B69** (job page stuck on "loading…") needed no separate change; another fix already covered it.
- **New files:** `src/server/httpError.ts`, `src/server/omni/folderCache.ts`, `src/server/storage/baseUrl.ts`, `src/web/lib/dashboardCache.ts`.
- **Dependencies:** none added. `dotenv` moved to `dependencies` because the server now loads `.env`. `pnpm build` now clears `dist` first.

### Behaviour changes to know about

- **Retry** only re-runs the failed destination/document pairs, so it no longer creates same-name duplicates. Retried imports get their description and labels. Retry is refused (409) while the job is running, and its errors show on the job page.
- **Interrupted jobs:** on startup, jobs left `running` by a restart are marked failed or partial and can be retried.
- **Same-name docs:** Preview refuses when two selected dashboards share a name, or when the destination folder already holds more than one dashboard with that name.
- **Empty first:** deletes run only after every export has succeeded. A delete whose doc is already gone counts as success.
- **One job per destination folder:** a second Execute or Retry on a folder in use returns 409.
- **Execute matches Preview:** if the destination changed after Preview, nothing runs; the new plan is shown and Execute must be clicked again.
- **Folder path:** imports use the path Omni reports for the folder ID, not the typed Folder Path.
- **Re-run verify:** an unchanged dashboard with CTE or tab-only-field tiles is still verified, and a broken tile turns the job red.
- **No retries on writes:** imports, publishes and schema refreshes are no longer retried after a timeout or 5xx. Import timeout is 180s.
- **Vault:** writes are safe if interrupted (`vault.enc.bak` appears). A missing vault is not silently recreated; first-time setup asks for the passphrase twice.
- **Local access only:** requests whose Host or Origin is not `localhost`/`127.0.0.1`/`[::1]` get 403.
- **Instances:** Base URL is reduced to its origin; http (except localhost), credentials in the URL and padded API keys are rejected. The server reads `.env`.
- **Dashboard page:** fixed date-range filter, "App off" toggle, schema-refresh status, cache staleness and several counting errors.

### What to test first

1. Re-run a migration onto a destination that already has the dashboards: schedules survive, no duplicates.
2. Make one import fail, click **Retry**, then click it again.
3. Run with **Empty each destination folder** on.
4. Restart the server mid-job and reopen the job in History.
5. Unlock and Lock, and add or edit an instance.

### Known residual gap

The update step still finds the destination doc by name at run time, so a change in the seconds after Execute can still slip through (see "Persist the planned destination document id" below).

At minimum, add a visible warning to the update note when the source has queryModels that were not synced.
- **Persist the planned destination document id and choose the keeper by schedules or age** (impact: high, effort: medium; src/server/jobs/planner.ts, src/server/jobs/runner.ts, src/server/storage/db.ts, src/server/storage/repo.ts, src/shared/types.ts): The planner picks a keeper, but runner.ts:246 re-lists the whole destination folder per update item and re-picks by name and newest updatedAt, so the run can target a different doc than the preview and costs one rate-limited listing per item. Add destDocId to JobPlanStep/job_items and use it directly (fail clearly if it vanished). Prefer the doc that has schedules (GET /api/v1/schedules) or the oldest one as keeper instead of newest updatedAt, since the extra duplicate is usually the recent accident and the original holds the schedules. Compare timestamps with Date.parse, not localeCompare, and filter candidates by hasDashboard. Optionally record a (source doc, dest instance, dest doc) link table so renames do not create duplicates.
- **Refuse to wipe a destination when the source has no matching tabs** (impact: high, effort: small; src/server/jobs/updatePatch.ts): buildUpdatePatch defaults srcTabs to {} and matches tabs purely by key. If the source state has no tabs, or zero tab keys overlap the destination (a same-name doc not created from this source), every destination tab is nulled and re-created, which destroys the tile-level schedules this tool exists to keep. Throw a clear error (or require explicit confirmation) when the source has no tabs, or overlap is zero while the destination has tabs.
- **Snapshot destination state before publishing and roll back or flag a failed verify** (impact: high, effort: medium; src/server/jobs/runner.ts, src/server/omni/client.ts): destState is already read before patching, but it is only written to data/diff on a 400. If verify finds broken tiles after publish, the live dashboard (possibly with active schedules) stays broken and there is no stored copy to restore. Persist the pre-update state on every successful publish, and on verify failure offer or perform a re-publish of that state. Also treat 'every tile timed out' as a failure rather than a success note.
- **Handle existing destination drafts explicitly** (impact: medium, effort: small; src/server/omni/client.ts, src/server/jobs/runner.ts, docs/in-place-update-test-plan.md): patchAndPublish always DELETEs the destination's main draft, silently discarding a colleague's unpublished work, and the diff base (destState read at runner.ts:253) is read before that discard. Detect an existing draft first, read destState after the discard, and either refuse, require an opt-in option, or at least note 'discarded existing draft' on the item. If publish fails after a successful PATCH, best-effort DELETE the draft so a failed update leaves no residue. Add a test-plan case for a destination draft with content.
- **Normalise both states before diffing and add a convergence check** (impact: medium, effort: small; src/server/jobs/updatePatch.ts, src/server/jobs/runner.ts): Several comparisons depend on Omni's exact representation: description '' vs null, absent controls/settings/containers on the source (leaves stale filters or layout), and already-null destination tabs (makes hasContentChanges true on every run, publishing a version each time). Add a normalizeState() step (coalesce ''/null, default missing sections, skip null deletions for tabs already gone, build live key sets from non-null entries only). After publish, re-read the destination and re-run buildUpdatePatch; if non-empty, flag 'update does not converge'. Use a plain code-point comparator in canonical() instead of localeCompare.
- **Send more than 48 changed tabs by chunking draft PATCHes** (impact: medium, effort: medium; src/server/jobs/updatePatch.ts, src/server/omni/client.ts): buildUpdatePatch throws when more than 48 tabs would be sent, so large dashboards can never be updated in place and fail on every retry. Drafts accumulate patches until publish, so batch tabs in groups of at most 48, put order and null deletions in the last batch, and publish once. Verify against a test dashboard that successive draft PATCHes merge before relying on it.
- **Make verification cheaper and honest (planOnly, documented cache value, no vacuous success)** (impact: high, effort: medium; src/server/jobs/queryModels.ts, src/server/omni/client.ts, src/server/jobs/runner.ts): verifyTiles executes every tile on the warehouse with cache 'SkipCache' (client.ts:238), which is not in the swagger enum (disabled|normal|refresh|refresh_all). Try planOnly:true for compile-only checks (no warehouse cost or 60s timeouts) and use 'disabled'; validate on one good and one broken dashboard first. Also: fail or warn when changed tabs exist but checked is 0 (v2 tab name vs export tile name mismatch); only treat 400/404/422 as tile failures and report 5xx/network errors as unverified; wrap extractQueryError's JSON.parse in try/catch; cap the note length; handle a runQuery response that is an object with jobIds/completedQueries instead of returning []; stop retrying 5xx on /query/run.
- **Replace the regex YAML handling in queryModels with a real YAML parser** (impact: medium, effort: medium; src/server/jobs/queryModels.ts): parseQueryViewAliases and fixRawColumnRefs assume exact 2/4-space indentation and unquoted keys; trailing comments, column-0 comments, quoted keys and flow maps silently produce unresolved refs, and the raw-ref rewrite can alter quoted strings that are not SQL. Use the yaml package to read query.fields and restrict ref rewriting to sql/expression values. Also order YAML writes topologically so a CTE that references a later-alphabetical CTE is written after its dependency.
- **Mirror label removals on update and surface non-fatal warnings as item notes** (impact: low, effort: small; src/server/jobs/runner.ts, src/server/omni/client.ts): The meta step only adds labels (setDocumentLabels with an empty remove list), so a label removed at the source persists at the destination. - **Skip unchanged dashboards using the stored export hash** (impact: low, effort: medium; src/server/jobs/runner.ts, src/server/storage/repo.ts): exportHash is written to job_items (runner.ts:187) but never read. ### Security hardening (localhost tool)

- **Validate Host/Origin and send security headers** (impact: high, effort: small; src/server/main.ts, src/web/lib/api.ts, vite.config.ts): The server binds to 127.0.0.1 but never checks Host or Origin (confirmed: no onRequest hook in src). A page using DNS rebinding can reach the API while the vault is unlocked (jobs with emptyFirst, /api/actions/run as a request proxy, instance edits), and body-less POSTs like /api/lock and /api/jobs/:id/retry are simple cross-site requests. Add an onRequest hook that rejects Host other than 127.0.0.1/localhost:PORT (allow the Vite dev origin in dev), rejects foreign Origin on non-GET, and requires a custom header (or per-process token cookie) on mutating routes. Add CSP default-src 'self' with frame-ancestors 'none', X-Frame-Options, nosniff, Referrer-Policy and Cache-Control: no-store on /api.
- **Outbound URL policy for post-migration actions and /api/actions/run** (impact: medium, effort: small; src/server/jobs/postMigration.ts, src/server/routes/jobs.ts): These endpoints fetch any URL, method, headers and body and return the response, with no timeout (undici default is about 5 minutes, which can leave a job 'running'). Restrict to http(s), set redirect:'manual', add AbortSignal.timeout(30s), cap stored and returned responseBody (about 64KB), and optionally block loopback and link-local ranges or allowlist hosts.
- **Constrain and normalise instance input** (impact: medium, effort: small; src/server/routes/instances.ts, src/server/storage/vault.ts, src/web/pages/Instances.tsx): baseUrl is z.string().url(), which accepts http, ftp and URLs with paths that break `${base}${path}`; apiKey accepts an empty string on create; trailing newlines in pasted keys make fetch throw invalid-header TypeErrors that are retried. Require https (http only for localhost), normalise to origin, trim fields, reject credentials in the URL, require a non-empty key on create, require key re-entry when the host changes on PUT (otherwise the stored key is redirected), enforce unique (role, label), validate UUID ids, use a partial schema for PUT so omitted fields do not wipe values, and 404 for missing ids.
- **Stop sending and persisting action header secrets in clear text** (impact: medium, effort: medium; src/server/routes/instances.ts, src/server/storage/vault.ts, src/server/storage/repo.ts, src/web/pages/Migrate.tsx): GET /api/instances returns every post-migration action's header values (usually bearer tokens), and createJob copies them into jobs.post_migration_actions in SQLite outside the vault. Return masked values and treat an unchanged mask as keep-existing, render value inputs as type=password, and store a reference to the instance's actions on the job rather than the secrets. Also truncate stored webhook responses.
- **Make vault writes atomic and add a versioned, stronger file format** (impact: high, effort: medium; src/server/storage/vault.ts, src/server/storage/crypto.ts): persist() writes straight onto vault.enc, so a crash, OneDrive lock or tsx-watch kill can truncate the only copy of every API key, and in-memory state is mutated before the write. Write to a temp file, fsync, rename, keep a .bak, and roll back memory on failure. Add a header (magic, version, scrypt N/r/p, salt) authenticated as GCM AAD so KDF cost can be raised later (OWASP N=2^17), pass authTagLength to createDecipheriv, check minimum blob length, and return distinct errors for wrong passphrase vs corrupt vault so a damaged file does not burn the unlock budget. Switch to async crypto.scrypt.
- **Passphrase policy, unlock rate limits and idle auto-lock** (impact: medium, effort: small; src/server/routes/unlock.ts, src/server/routes/instances.ts, src/web/pages/Unlock.tsx, src/web/pages/Settings.tsx, src/server/storage/vault.ts): The server accepts a 1-character passphrase on create and change, creation has no confirm field, change-passphrase is a second guessing oracle limited only by the global 300/min, and the unlock limiter counts successful unlocks and is shared by every loopback caller. Require 12+ characters and a confirm field, add a tight route limit and backoff on change-passphrase, count only failed unlocks, disable the submit button while pending, show a retry countdown on 429, add autocomplete attributes (new-password, current-password, off for the API key field), and add an idle auto-lock that is skipped while a job runs.
- **Clear client caches on lock** (impact: medium, effort: small; src/web/App.tsx, src/web/pages/Dashboard.tsx): Lock only invalidates unlock-status. React Query keeps instance and embed-user data, and Dashboard writes embed-user names, usernames and groups to localStorage (dashboard:cache:*) that survives lock and restarts, which matters given Stord's customer-PII obligations. Call qc.clear() and remove dashboard:* keys on lock, wrap lsSetCache in try/catch, and consider sessionStorage or memory only.
- **Block Vite dev server from serving data/ and .env, and tighten .gitignore** (impact: medium, effort: small; vite.config.ts, .gitignore): Vite's root is src/web, so server.fs.allow covers the workspace and data/vault.enc, data/migrator.db and data/diff/*.json are reachable via /@fs/ from any localhost origin. Add server.fs.deny for .env, data and certificate files. In .gitignore anchor /data/, /dist/, /TODO, fix the pnpm log pattern, and add *.enc, *.db*, *.log, local editor/tool settings files and coverage/.
- **Stop leaving plaintext secrets behind after seeding** (impact: medium, effort: small; src/server/scripts/seed-env.ts, src/server/scripts/cli.ts, README.md, .env.example): After seed-env the plaintext API keys stay in .env (cloud-synced here), and cli.ts accepts VAULT_PASSPHRASE from the environment, which defeats the vault. Offer to blank the *_API_KEY lines after a successful seed, warn when VAULT_PASSPHRASE is used and prefer the prompt or stdin, and fix README wording ('AES-256-GCM with scrypt', .env is not deleted automatically).

### Data storage, config and server plumbing

- **Move data/ out of the OneDrive tree and resolve paths from one DATA_DIR** (impact: high, effort: small; src/server/storage/db.ts, src/server/storage/vault.ts, src/server/jobs/runner.ts, README.md, .env.example): vault.enc, migrator.db plus -wal/-shm and data/diff dumps all sit under OneDrive, where sync can lock or conflict with a live WAL database and uploads dashboard definitions. VAULT_PATH, DB_PATH and './data/diff' are also cwd-relative, so running from another directory silently creates a second empty vault and DB (and unlock() would accept any passphrase). Add one config module with a DATA_DIR defaulting to an OS app-data path resolved from the project root, derive all three paths from it, warn at startup when it sits in OneDrive/Dropbox/iCloud, and add retention, restricted mode and filename sanitising for data/diff dumps.
- **Wire up fastify-type-provider-zod (or drop it), a global lock hook and one error envelope** (impact: high, effort: medium; src/server/main.ts, src/server/routes/jobs.ts, src/server/routes/instances.ts, src/server/routes/folders.ts, src/server/routes/dashboard.ts, src/server/routes/unlock.ts, package.json): The type provider is a dependency but unused (confirmed), every route hand-parses with zod, ZodError becomes a 500, dashboard.ts casts req.body (a missing body throws a TypeError), and the isUnlocked 423 check is copy-pasted about 25 times (the SSE route missed it).
